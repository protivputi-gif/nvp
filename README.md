# VLESS Finder

Однофайловый скрипт (**v1.3.0**, ~1500 строк) для поиска и проверки рабочих
VLESS-нод. GitHub API-поиск **не используется** — только 11 публичных
подписок, ссылки на них в списке `KNOWN_SUBSCRIPTION_URLS`.

## Окружение и установка

Требования: **Python 3.10+** (используются `X | None`-аннотации и asyncio-API
этого поколения), Linux/macOS (скрипт POSIX-ориентированный), доступ в интернет.
Зависимости: `aiohttp`, `rich`, `PySocks`. Бинарник `xray` ставится самим
скриптом (`--install`) либо берётся из PATH.

### Вариант 1 — venv (рекомендуется)

```bash
# создать окружение
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# зависимости
pip install --upgrade pip
pip install aiohttp rich PySocks

# скачивать/проверить версию pip не обязательно, но полезно зафиксировать:
pip freeze > requirements.txt      # опционально: для воспроизводимости
```

### Вариант 2 — conda

```bash
conda create -n vless-finder python=3.12 -y
conda activate vless-finder
pip install aiohttp rich PySocks
```

### Вариант 3 — системный Python без виртуального окружения

```bash
pip install --user aiohttp rich PySocks
```

### Проверка окружения

```bash
python -c "import aiohttp, rich, socks; print('deps OK')"   # должно напечатать: deps OK
python vless_finder.py --version                            # версия скрипта
python vless_finder.py --install                            # скачать xray в ./xray_bin
./xray_bin/xray version                                     # убедиться, что бинарник рабочий
```

Деактивация окружения по окончании работы: `deactivate`.

## Быстрый старт

```bash
# если бинарника xray нет рядом — скачать автоматически:
python vless_finder.py --install

# полный прогон (все источники, результаты в ./):
python vless_finder.py

# разведочный прогон: случайная выборка 5000 нод, 100 параллельных проверок:
python vless_finder.py --limit 5000 -c 100

# воспроизводимая выборка (тот же seed → тот же порядок проверки):
python vless_finder.py --limit 1200 --shuffle-seed 42

# без перемешивания — строго по порядку подписок:
python vless_finder.py --limit 500 --no-shuffle
```

Скрипт можно скопировать куда угодно и запустить — он сам найдёт `xray`
в каталоге рядом с собой (`xray_bin/`) или в PATH.

## Как это работает

1. **Сбор.** Параллельно скачиваются тексты всех подписок, извлекаются
   ссылки `vless://` (включая base64-обёртки), идёт дедупликация (~159 тыс.
   уникальных нод). Затем ноды **случайно перемешиваются** (воспроизводимо
   через `--shuffle-seed N`), и только после этого применяется `--limit N` —
   выборка репрезентативна по всей базе, а не «первые N по ходу подписки».
2. **Проверка каждой ноды** — в изолированном процессе `xray` с локальным
   SOCKS5-прокси (поддержка TLS / Reality / WebSocket / gRPC / XHTTP):
   - TCP-пинг хоста (3 замера) — отсев мёртвых адресов;
   - быстрая предпроверка туннеля (HTTP CONNECT через локальный SOCKS5-xray) —
     отсев нод, у которых туннель не устанавливается вовсе;
   - доступность обязательных сайтов через прокси: **youtube + telegram +
     nvidia**. Живой считается нода, у которой доступны ВСЕ три — и не разово,
     а **стабильно во всех раундах проверки** (основной + 2 контрольных с
     паузой ~3 с; число настраивается `--stability N` / `VF_STABILITY_ROUNDS`).
     Для youtube и telegram проверяется главная страница (не служебный
     /generate_204): ответ должен реально загружаться (не менее 1 КБ тела) —
     как при фактическом просмотре/скачивании видео. Скорость скачивания
     меряется в каждом раунде; итоговая скорость — худший (минимальный)
     результат по раундам, поэтому «вспышечные» ноды не получают ложно-высокий
     рейтинг.
     (Дополнительные google/cloudflare/wikipedia из проверки исключены:
     на отбор они не влияли, только замедляли прогон.)
   - замер скорости скачивания.
3. **Ранжирование.** Оценка 0–100: `0.45·скорость + 0.35·пинг + 0.20·покрытие`.
   Покрытие = 100% только если все 3 сайта открывались во всех раундах
   (у живых нод в good_vless.txt оно всегда 100 — колонка служит
   доказательством стабильности).
4. **Вывод:**
   | Файл | Содержимое |
   |---|---|
   | `good_vless.txt` | все живые ноды |
   | `best_vless.txt` | топ лучших (по умолчанию 100, порог ≥ 2 Мбит/с) |
   | `report.csv` | детальная таблица: score, скорость (мин. по раундам), пинг, покрытие %, число раундов, скорости каждого раунда, худший отклик сайта, отклик каждого сайта, имя, ссылка |
   плюс итоговая таблица в терминале (rich).

## Параметры CLI

| Флаг | Описание | По умолчанию |
|---|---|---|
| `-c, --concurrency N` | одновременных проверок | 100 |
| `--min-speed MBPS` | мин. скорость для топ-файла, Мбит/с | 2.0 |
| `--top N` | сколько лучших нод сохранить | 100 |
| `--limit N` | проверить случайную выборку из N ссылок (0 = все) | 0 |
| `--shuffle-seed N` | зерно перемешивания для воспроизводимого порядка проверки | случайное |
| `--no-shuffle` | не перемешивать: проверять строго по порядку подписок | — |
| `--stability N` | контрольных раундов стабильности после основного (0 = один замер; нода проходит лишь при 100% сайтов и пороге скорости во всех раундах) | 2 |
| `--out DIR` | папка для результатов | текущая |
| `--from-file FILE` | взять ссылки из локального файла вместо скачивания | — |
| `--install` | автоматически скачать xray, если его нет | — |
| `--version` | показать версию | — |

Переменные окружения (тонкая настройка): `VF_MIN_SPEED`, `VF_LATENCY_SAMPLES`,
`VF_STABILITY_ROUNDS`, `VF_STABILITY_GAP`, `VF_MAX_CONCURRENT`,
а также таймауты/число потоков — см. докстринг в начале `vless_finder.py`.

## Источники (файл subscriptions.txt)

Список подписок больше НЕ зашит в код — он берётся из файла `subscriptions.txt`
в рабочей папке: по одному URL на строку, пустые строки и строки с `#`
игнорируются. Если файла нет, при первом запуске он создаётся автоматически
с дефолтным списком живых источников. Чтобы добавить/удалить подписку —
просто отредактируйте файл, правка кода не требуется.

Порядок поиска файла: `--sources FILE` → `./subscriptions.txt` → переменная
окружения `VF_SOURCES_FILE`. Дополнительно к списку из файла дописываются
`known_subscriptions.txt` (в папке результатов) и `VF_EXTRA_SOURCES`
(URL через запятую). Итоговый фактический список сохраняется в
`subscription_urls.txt` (артефакт прогона).

## Кодовая структура (один файл, 11 секций)

Модели → Конфигурация → Парсинг подписок → Источники → Генератор конфига xray →
Менеджер процессов xray → Сетевые зонды → Конвейер проверки и скоринг →
Отчёты → Автоустановка xray → CLI.

## Примечания

- Порядок проверки: ноды перемешиваются перед применением `--limit`, поэтому
  разные прогоны опрашивают разные части базы (~159 тыс. нод). Для сравнения
  результатов или возобновления прерванного прогона используйте один и тот же
  `--shuffle-seed N`; режим «строго по подпискам» — `--no-shuffle`.
- Ориентир по качеству публичной базы (прогон 2026-10-16, 5000 случайных нод,
  `-c 100`, ~11 мин): живых ~1% (57 нод). Типичные причины отсева: ~25% —
  мёртвые хосты (TCP не отвечает), ~45% — туннель жив, но сайты не открываются.
  Для набора большего числа рабочих нод увеличивайте `--limit` или делайте
  несколько прогонов с разными seed.
- Дедупликация нормализует написания параметров (`type=websocket` vs `type=ws`,
  подразумеваемый/`auto` `security`) через единый резолвер `resolve_security()`,
  поэтому одна физическая нода в любом виде схлопывается в одну запись.
- `xray.zip` и `xray_bin/` — локальные артефакты (в .gitignore), в репозиторий не попадают.
